## Codebase Patterns
- 编译器配置：Spring Boot 4.x BOM 会覆盖 maven.compiler.source/target 属性，需要在 maven-compiler-plugin 配置中直接硬编码 Java 版本（如 `<source>17</source>`）
- 根 pom.xml 的 release profile 默认激活（activeByDefault=true），其中的编译器配置也需要同步更新
- TestContainers Singleton 模式：使用 static final + static initializer 启动容器，整个 JVM 只启动一次
- 测试 SQL 脚本需移除 `CREATE database`、`use` 和 `commit;` 语句，因为 TestContainers 的 withDatabaseName 会自动创建数据库
- MySQLContainerHolder 位于 com.xxl.job.admin.test.support 包下
- MapperITBase 使用 @MybatisTest + @AutoConfigureTestDatabase(replace=NONE) + @Transactional
- @DynamicPropertySource 需配置 mybatis.mapper-locations 和 hikari.maximum-pool-size=5
- TestFixtures 提供 6 个工厂方法：createJobGroup、createJobInfo、createJobLog、createLogGlue、createLogReport、createUser
- Spring Boot 4.x 迁移注意事项：
  - `@AutoConfigureTestDatabase` 包路径从 `org.springframework.boot.test.autoconfigure.jdbc` 改为 `org.springframework.boot.jdbc.test.autoconfigure`
  - `@MybatisTest` 会强制加载主应用类（XxlJobAdminApplication），可能导致日志配置问题
  - logback-test.xml 需要在测试资源目录创建以覆盖主 logback.xml 配置
- TestContainers 与 Spring Boot 4.x 集成问题：
  - TestContainers 在 Spring 应用上下文加载期间尝试检测 Docker 环境
  - MySQLContainerHolder 需使用延迟初始化（lazy initialization）避免在 Spring 条件评估期间启动容器
  - Docker socket 连接问题：TestContainers 尝试通过 Unix socket 连接但可能收到空响应

- **Learnings for future iterations:**
  - Spring Boot 4.x 中 `@AutoConfigureTestDatabase` 包路径从 `org.springframework.boot.test.autoconfigure.jdbc` 改为 `org.springframework.boot.jdbc.test.autoconfigure`
  - `@MybatisTest` 会检测并强制加载主应用类（XxlJobAdminApplication），即使使用 `classes` 参数指定测试配置类
  - TestContainers 在 Spring 应用上下文加载期间（特别是 `DataSourceAutoConfiguration` 条件评估时）尝试检测 Docker 环境
  - 延迟初始化 MySQLContainerHolder 可以避免在类加载时启动容器，但 `@DynamicPropertySource` 方法执行时仍会触发初始化
  - Docker 环境检测失败会被 TestContainers 缓存，需要清除缓存（mvn clean）才能重试
  - TestContainers 1.20.4 与 Docker Desktop 在 macOS 上的 socket 连接可能存在兼容性问题
  - `logback-test.xml` 放在 `src/test/resources/` 下会覆盖 `src/main/resources/logback.xml`
  - Maven Surefire 插件可通过 `<environmentVariables>` 配置传递环境变量给测试
- **待解决问题：**
  - TestContainers Docker 环境检测失败，错误信息：`Could not find a valid Docker environment` 和 `Previous attempts to find a Docker environment failed. Will not retry`
  - 可能需要在 CI/CD 环境中配置 DOCKER_HOST 环境变量或使用 TestContainers 配置文件
  - 考虑降级 TestContainers 版本或使用替代的测试数据库方案（如 H2 内存数据库）
