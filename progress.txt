## Codebase Patterns
- 编译器配置：Spring Boot 4.x BOM 会覆盖 maven.compiler.source/target 属性，需要在 maven-compiler-plugin 配置中直接硬编码 Java 版本（如 `<source>17</source>`）
- 根 pom.xml 的 release profile 默认激活（activeByDefault=true），其中的编译器配置也需要同步更新
- TestContainers Singleton 模式：使用 static final + static initializer 启动容器，整个 JVM 只启动一次
- **TestContainers SQL 初始化脚本要求：**
  - **必须移除所有注释（包括 `##` 和 `#` 注释）**，因为 TestContainers 的脚本解析器会将注释与后续 SQL 语句合并，导致语法错误
  - **每个 SQL 语句必须以分号结尾**
  - **移除 `CREATE database`、`use` 和 `commit;` 语句**，因为 TestContainers 的 withDatabaseName 会自动创建数据库
- MySQLContainerHolder 位于 com.xxl.job.admin.test.support 包下
- MapperITBase 使用 @MybatisTest + @AutoConfigureTestDatabase(replace=NONE) + @Transactional
- @DynamicPropertySource 需配置 mybatis.mapper-locations 和 hikari.maximum-pool-size=5
- TestFixtures 提供 6 个工厂方法：createJobGroup、createJobInfo、createJobLog、createLogGlue、createLogReport、createUser
- **测试数据长度限制：**
  - XxlJobGroup.title 是 varchar(12)，测试数据必须 ≤12 个字符
  - 其他字段长度限制需参考数据库表定义
- Spring Boot 4.x 迁移注意事项：
  - `@AutoConfigureTestDatabase` 包路径从 `org.springframework.boot.test.autoconfigure.jdbc` 改为 `org.springframework.boot.jdbc.test.autoconfigure`
  - `@MybatisTest` 会强制加载主应用类（XxlJobAdminApplication），可能导致日志配置问题
  - logback-test.xml 需要在测试资源目录创建以覆盖主 logback.xml 配置

  - **innodb_lock_wait_timeout 设置：** `SET SESSION innodb_lock_wait_timeout=1` 是 session 级别设置，只影响当前会话。测试时需在获取锁之前设置。
  - **CountDownLatch 协调线程：** 使用两个 CountDownLatch 协调线程执行顺序：threadAStarted 通知线程 B 可以开始，threadBFinished 等待线程 B 完成。
  - **Exception 类型限制：** AtomicReference<Exception> 不能存储 AssertionError，因为 AssertionError 不是 Exception 的子类。需使用 RuntimeException 包装。
